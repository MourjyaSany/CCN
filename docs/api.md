# NetShield-GNN — REST API Reference

The API is generated by FastAPI, so the authoritative, always-current reference
is the interactive documentation the server itself publishes:

| | |
|---|---|
| **Swagger UI** | <http://127.0.0.1:8000/docs> |
| **ReDoc** | <http://127.0.0.1:8000/redoc> |
| **OpenAPI JSON** | <http://127.0.0.1:8000/openapi.json> |
| **Dashboard** | <http://127.0.0.1:8000/> |

```bash
./run.sh dashboard                 # or: python scripts/serve.py
```

> **Safety.** The API surface contains **no host, port or target parameter
> anywhere**. Its only state-changing endpoints start and stop a simulation
> inside this process. There is no code path by which a request can cause a
> packet to leave the machine.

## System

### `GET /api/health`

```json
{
  "status": "ok",
  "version": "1.0.0",
  "engine": "Python discrete-event emulation",
  "ns3_available": false,
  "gnn_backend": "torch-geometric",
  "detectors_loaded": ["graphsage", "random_forest", "threshold"],
  "database": "/app/data/netshield.db",
  "dataset_available": true
}
```

`engine` and `ns3_available` come from a real capability probe. If NS-3 were
installed, `engine` would read `"NS-3 simulation"` — the field is never
cosmetic.

### `GET /api/scenarios`

One entry per experiment, with device counts, attack type and timing, so a
client can populate a scenario picker without reading the YAML.

### `GET /api/environment`

The full probe used to label results: Python version and platform, the version
of every key library, which external tools are on `PATH`, and the complete NS-3
detection record including each individual check that was attempted.

## Simulation control

### `POST /api/simulation/start`

```json
{
  "scenario": "exp8_mitigation",
  "speed": 5.0,
  "mitigation": true,
  "detector": "graphsage",
  "duration_s": null,
  "overrides": {
    "attack.type": "slowloris",
    "attack.packets_per_second": 12,
    "network.topology.family": "multi_gateway"
  }
}
```

| Field | Meaning |
|---|---|
| `scenario` | Experiment name from `/api/scenarios` |
| `speed` | Simulated seconds per wall-clock second. `0` runs as fast as possible. Pacing only ever *delays* the worker thread — it never changes the simulation, whose results are identical with or without it. |
| `mitigation` | Force the closed loop on or off; `null` uses the scenario's own setting |
| `detector` | Detector driving detection and mitigation |
| `duration_s` | Optional duration override |
| `overrides` | Sparse dotted-key configuration overrides from the attack builder. **Allowlisted** — see below. |

Returns `409` if a simulation is already running, `404` for an unknown
scenario, and `400` if an override key is outside the allowlist.

#### The override allowlist

`overrides` is the only way the API accepts arbitrary configuration, and it
is deliberately narrow. `netshield.api.state.sanitise_overrides` accepts keys
under `attack.*`, `network.topology.*`, `mitigation.*`, `detection.*`,
`features.*` and `traffic.*`, plus the named keys `simulation.n_iot_devices`,
`simulation.n_attackers`, `simulation.duration_s` and `seed`. Everything else
— `paths.*`, `api.host`, `logging.*`, `simulation.engine`, and any key
containing `..` — is rejected with a `400`.

This is what preserves the project's safety property: there is still no host,
port, interface or real-world target parameter anywhere in the API surface.
`attack.target` accepts only a role (`cloud`, `gateway`) or a node id from the
topology this process just built; anything else raises `AttackSafetyError`.

```bash
curl -X POST http://127.0.0.1:8000/api/simulation/start \
     -H 'Content-Type: application/json' \
     -d '{"scenario":"exp8_mitigation","speed":5,"mitigation":true}'
```

### `POST /api/simulation/stop`

Requests a stop at the next window boundary, so the run always terminates in a
consistent state. Safe to call when idle.

### `GET /api/simulation/status`

```json
{
  "state": "running",
  "scenario": "exp8_mitigation",
  "run_id": "exp8_mitigation_seed48_3e48c153342a",
  "engine_label": "Python discrete-event emulation",
  "sim_time_s": 45.0,
  "duration_s": 130.0,
  "progress": 0.3462,
  "mitigation_enabled": true,
  "detector": "graphsage",
  "error": ""
}
```

`state` is one of `idle`, `running`, `stopping`, `completed`, `failed`. On
`failed`, `error` carries the exception type, message and a short traceback —
failures are surfaced, not swallowed.

## Live network views

### `GET /api/network/status`

The aggregate the dashboard KPI tiles read: device and router counts, suspicious
/ malicious / mitigated node counts, whether an attack is currently active,
packet rate, throughput, latency (all traffic and legitimate only), packet loss,
uplink utilisation, and the maximum detector confidence this window.

### `GET /api/network/topology`

Nodes and links, each node annotated with its live classification:

```json
{
  "name": "iot-edge-cloud-3tier",
  "n_nodes": 35,
  "n_links": 34,
  "nodes": [
    {
      "node_id": "atk-00", "kind": "attacker", "ip": "10.10.9.2", "tier": 3,
      "parent": "rtr-0", "is_attacker": true, "probability": 0.998,
      "predicted": "MALICIOUS", "packet_rate": 1502.4, "mitigation": "isolate"
    }
  ],
  "links": [
    {
      "source": "gw-0", "target": "cloud-0",
      "bandwidth_bps": 20000000.0, "delay_ms": 12.0, "queue_packets": 120
    }
  ]
}
```

`is_attacker` is **ground truth** and is included so the dashboard can show
whether the model is right. It is never a model input.

### `GET /api/traffic/current`

The latest completed window plus the ten highest-rate sources.

### `GET /api/metrics`

The full per-window QoS series for the current run, plus the attack profile and
`first_mitigation_s`, so a client can draw the shaded attack band and the
mitigation marker without extra requests.

## Detection and mitigation

### `GET /api/alerts?limit=100&min_confidence=0.8`

Detections at or above the trigger, newest first, each with a human-readable
`message`. Defaults to `detection.mitigation_trigger_probability` from the
configuration.

### `GET /api/detections?window=8&limit=500`

Raw per-node rows including the full three-class probability vector — useful for
plotting confidence on benign windows, which `/api/alerts` deliberately omits.

### `GET /api/mitigation?limit=100`

```json
[
  {
    "timestamp": 45.0, "window": 8, "node": "atk-00", "ip": "10.10.9.2",
    "action": "isolate", "confidence": 0.9985, "detector": "graphsage",
    "reason": "p=1.00 >= 0.95 for 2 consecutive windows",
    "result": {"enforcement_point": "gateway-ingress", "dropped_packets": 97912}
  }
]
```

`action` is one of `rate_limit`, `block`, `isolate`, `release`.

## Experiments and results

### `POST /api/experiment/run`

Runs one experiment to completion with pacing disabled. Returns immediately;
poll `/api/simulation/status` until `state` is `completed`.

### `GET /api/results`

Evaluation results produced by `scripts/evaluate.py`. When evaluation has not
been run, it says so rather than returning empty tables:

```json
{
  "available": false,
  "message": "No evaluation results yet. Run 'python scripts/evaluate.py' ...",
  "figures": []
}
```

### `GET /api/figures/{name}`

Serves a PNG from `results/figures/`. Path traversal is rejected with `400`.

## Catalogue

These describe what the simulator *can* be asked to do. The dashboard's attack
builder renders itself from them, so a new configuration knob appears in the UI
as soon as it exists in `config/default.yaml`.

### `GET /api/topologies`

```json
[
  {
    "name": "multi_gateway",
    "description": "Several gateways homing to the cloud; enforcement is distributed.",
    "parameters": {"gateways": 3, "routers_per_gateway": 2}
  }
]
```

### `GET /api/attacks`

```json
[
  {
    "name": "slowloris",
    "description": "Application: many half-finished connections held open to exhaust the connection table.",
    "layer": "application"
  }
]
```

### `GET /api/attacks/schema`

Returns `attack_types`, `rate_profiles`, `topology_families`, the current
`defaults` from the configuration, the override allowlist, and sanity `limits`
for the numeric fields.

### `POST /api/attack/preview`

Resolves a builder configuration **without running it**, so an impossible
combination is reported immediately rather than after a simulation.

```json
{
  "scenario": "exp2_udp_flood",
  "overrides": {"attack.type": "slowloris", "attack.packets_per_second": 12}
}
```

On success:

```json
{
  "valid": true,
  "profile": { "...": "the fully resolved AttackProfile" },
  "topology_family": "tree",
  "n_attackers": 4,
  "aggregate_pps": 48.0,
  "estimated_packets": 1440,
  "overrides": { "...": "the sanitised overrides that would be applied" }
}
```

On an invalid configuration it returns `200` with `{"valid": false, "error": ...}`
— the configuration is bad, the request was not. A rejected *override key* is a
`400`, because that request was malformed.

## Results browsing

### `GET /api/figures`

Every generated figure with `name`, `url`, `size_bytes` and the `experiment` its
filename identifies.

### `GET /api/reports` and `GET /api/reports/{name}`

The list of generated markdown reports, and one report returned as
`{"name": ..., "markdown": ...}`. Path traversal is rejected with `400`.

### `GET /api/models`

The manifest of every trained detector on disk, each with a `loaded` flag
showing whether the API actually has it in memory — so a model that exists but
failed to load is visible rather than silently absent.

## Status codes

| Code | Meaning |
|---|---|
| `200` | Success |
| `400` | Malformed request (for example an invalid figure name) |
| `404` | Unknown scenario, experiment or figure |
| `409` | A simulation is already running |
| `422` | Request body failed Pydantic validation |

## A minimal client

```python
import time
import requests

BASE = "http://127.0.0.1:8000"

requests.post(f"{BASE}/api/simulation/start", json={
    "scenario": "exp8_mitigation", "speed": 8.0, "mitigation": True,
}).raise_for_status()

while True:
    status = requests.get(f"{BASE}/api/simulation/status").json()
    print(f"{status['state']:10} t={status['sim_time_s']:6.1f}s "
          f"({status['progress']:.0%})")
    if status["state"] in ("completed", "failed"):
        break
    time.sleep(2)

for action in requests.get(f"{BASE}/api/mitigation").json():
    print(f"t={action['timestamp']:6.1f}s  {action['action']:<10} "
          f"{action['node']}  p={action['confidence']:.3f}")

metrics = requests.get(f"{BASE}/api/metrics").json()
for window in metrics["windows"]:
    print(f"w{window['window']:<3} {window['throughput_mbps']:6.2f} Mbit/s  "
          f"loss {window['clean_loss_ratio']:.4f}  "
          f"util {window['uplink_utilisation']:.2f}")
```

## CORS

Configured in `config/default.yaml`:

```yaml
api:
  cors_origins: ["http://localhost:5173", "http://127.0.0.1:5173"]
```

The defaults allow the Vite dev server. The bundled dashboard is served from the
same origin and needs no CORS at all.
